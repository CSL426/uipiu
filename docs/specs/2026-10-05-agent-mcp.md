# 給外部 agent 用的 MCP 介面

- 狀態：Draft
- 日期：2026-10-05
- 相關：`2026-09-24-nidin-live-ordering.md`（點單即送）、`2026-10-01-ocard-group-ordering.md`（Ocard）

## 問題

本站的 REST API 是給自己的前端用的：瀏覽器跨站呼叫會被擋、主揪操作要登入 cookie、限流以來源 IP 計算。
使用者想讓別的 agent（Claude、Codex 等）直接查團、看菜單、點單，必要時代主揪開團和管理訂單。

## 決定

1. **MCP（streamable HTTP）**：後端提供 `/mcp`，經現有 nginx 對外，不另開埠。工具底層呼叫的就是
   公開頁用的點單即送流程，防重送、取消憑證、Nidin／Ocard 兩邊的行為完全一致。
2. **API key**：`Authorization: Bearer <key>`。主揪在管理頁發 key、撤銷 key；key 只在發出當下顯示一次，
   資料庫只存雜湊。每把 key 屬於發它的主揪。
3. **兩種權限**（使用者 2026-10-05 選定）：
   - `order`：查團、看菜單、點單、看跟團清單、撤回**這把 key 送出的**單。
   - `leader`：再加上開團（貼 Nidin／Ocard 連結）、撤回或刪除該主揪團裡任何一筆、標記收款。
     只能操作發這把 key 的主揪自己的團。
4. **限流**：依 key 計算（同一把 key 10 分鐘最多 60 筆送單），不再和其他來源共用 IP 額度。
5. **工具**：

   | 工具 | 權限 | 說明 |
   |---|---|---|
   | `list_groups` | order | 開著的團：平台、名稱、目前筆數與金額、外送門檻 |
   | `get_menu` | order | 品項與規格（必選、可選數量、加價），可用關鍵字篩選 |
   | `place_order` | order | 點單即送；`idempotency_key` 相同的重送不會重複下單 |
   | `list_orders` | order | 先和平台同步，再回傳每個人點了什麼、金額 |
   | `cancel_order` | order／leader | order：只能撤回自己送的；leader：自己團裡的任何一筆 |
   | `open_group` | leader | 貼揪團連結開團 |
   | `set_paid` | leader | 標記某人已收款／未收款 |

6. **REST 文件**：修好 `/api/docs`（原本去抓 `/openapi.json`，被 nginx 導到前端）。

## 不做

- 瀏覽器跨站呼叫（CORS）：對象是 agent，走伺服器端呼叫即可。
- 用 AI 解析自然語言點單的工具：呼叫端本身就是 agent，給它菜單讓它自己組單。

## 未解

- key 外洩時能下的單就是真的單；目前只靠撤銷與限流，沒有每日上限。
