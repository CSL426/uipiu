## P1：使用體驗與正式部署

- [ ] **Nidin 暫時無法連線時使用上次成功菜單，顯示資料時間。**
  - 目前 `GET /cart-sessions/{session_id}/menu` 每次向 Nidin 抓取，失敗未回退 SQLite；前端載入失敗會清除當前菜單。
  - 增加獨立的 `menu_fetched_at`，不要使用會因購物車變更而更新的 session `updated_at`。
  - 回應須可區分即時資料／快取，前端顯示「使用上次菜單」與最後成功抓取時間。
  - 暫時性的連線失敗、逾時與上游 5xx 可使用最後成功快照；授權、團購失效或資料格式錯誤須分別處理，不可全部隱藏。
  - 沒有舊快照時明確提示無法載入；失敗或不完整資料不得覆蓋成功快照。
  - 使用舊菜單可以瀏覽或整理草稿；正式送單前重新核對品項、價格、規格與供應狀態，失敗時不可宣稱送單成功。
  - 驗收：涵蓋成功更新、斷線、有／無快照、服務重啟、時間顯示與送單重新驗證的 API／前端測試。

- [ ] **收款狀態按團購隔離並持久化。**
  - `frontend/src/App.tsx` 目前以單一 localStorage key `nidin_paid_contributors` 儲存，內部只以姓名識別。
  - 同名訂購人在不同團購會共用「已收款」標記；換瀏覽器或換管理者則不會同步。
  - 驗收：至少使用團購 ID 與訂購人識別組合；若要多人對帳，保存於後端並套用管理權限。測試跨團同名、重新整理及多裝置一致性。

- [ ] **部署改為固定產物，重啟不安裝依賴。**
  - 前端 entrypoint 每次啟動執行 `npm install`，Compose 啟動的是 Vite 開發伺服器；後端預設啟用 reload。
  - 統一使用 pnpm 與提交的 lockfile；採 `builder` → `runner` 多階段建置，前端正式產物由 nginx 提供。
  - 後端依賴目前未鎖版本，也需建立可重現的依賴版本與容器測試流程。
  - 驗收：全新環境可建置；映像建好後，沒有套件站連線仍可重啟服務。一次只執行一個建置工作。

- [ ] **統一 Nidin API 預設設定。**
  - Compose 的預設為 `https://api.nidin.shop/api/menu/v2`，Python 預設與目前範例使用 `https://loctw-service-api.nidin.shop/shopper/v2`。
  - 已確認設定不一致；尚未驗證舊網址所有路由是否可用，不將它直接判定為失效。
  - 驗收：不依賴本機 `.env` 的新部署使用同一個已驗證端點；補設定回歸測試。

- [ ] **資料庫備份與還原。**
  - SQLite 位於 `app/data/cart.db`，含團購、購物車、菜單快照及團長憑證；目前由整個 `app/` 的 bind mount 保留。
  - 明確定義正式環境資料掛載、檔案權限與 SQLite 一致性備份流程；不要將資料庫放入 Git。
  - 驗收：在隔離環境實際還原後核對團購與購物車，再驗證重建容器後仍保留資料。

- [ ] **LLM 後備路徑的逾時與錯誤處理。**
  - `AgentParser._run_agy()` 沒有應用層逾時／清理機制；SDK 呼叫也沒有明確的應用層等待上限。
  - `parser.parse()` 的呼叫端未針對無後端、無效金鑰或供應商錯誤提供一致的使用者訊息。
  - 驗收：模擬逾時、無金鑰、供應商錯誤、非 JSON 回覆；不得無限等待或誤加購物車，並能改用手動選餐。
  - 目前量測只涵蓋抓菜單與圖譜快速解析，不代表 LLM 延遲或多人負載已驗證。

## 2026-09-18 已確認的實作方向（仍為 Draft）

- 使用者授權處理本機可完成項目，包含菜單備援；完成後 simplify，再展示首次提交範圍等待確認。
- 多主揪各自登入。第一位管理員由部署環境建立，可新增主揪帳號；每團由建立者管理，不能藉既有團購網址接管他團。
- 舊團購與既有全域 Nidin 憑證只遷移至第一位管理員。新憑證按本機主揪帳號隔離；一般點餐維持公開。
- 管理 API（新增、清空、整團送單、官方匯入、付款標記）驗證登入與團購歸屬；管理員不自動取得其他主揪的憑證。
- 登入使用 HttpOnly / SameSite Cookie、伺服器工作階段與密碼雜湊；同源檢查防止跨站管理操作。正式 HTTPS 部署需開啟 Secure Cookie。
- 收款按團購與訂購人保存 SQLite，其他裝置登入同一主揪可讀回；新增點單會清除該人的舊收款標記，舊 localStorage 不自動移入。
- 使用者希望免 DevTools 連結 Nidin 帳號；需查官方授權／回呼能力，先不假設其他網站能讀取其 LocalStorage。
